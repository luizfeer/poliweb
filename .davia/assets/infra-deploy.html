VPS Ubuntu 22 · Node 22 · PM2 6 · projeto em /home/ubuntu/projects/hail-mary

🔑 Variáveis de ambiente

Cada app tem seu próprio .env — nunca versionado. O PM2 injeta via interpreter_args: '--env-file=.env' (Node 22 nativo, sem dotenv).

  • apps/worker/.env — todos os workers de background
  • apps/media-processor/.env — daemon de mídia
  • apps/web/.env.local — Next.js (nunca usar no worker)

Variáveis obrigatórias do worker (copiar de apps/worker/.env.example): 

SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
WORKER_CITY_SLUG=carmo-do-rio-claro
GOOGLE_PLACES_API_KEY=          # Google Cloud Console → Places API (New)
BUNNY_STORAGE_ZONE=hail-mary
BUNNY_STORAGE_ACCESS_KEY=       # Bunny Dashboard → Storage → FTP & API Access
BUNNY_STORAGE_ENDPOINT=https://br.storage.bunnycdn.com
NEXT_PUBLIC_BUNNY_CDN_URL=https://hail-mary-crc.b-cdn.net
OPENAI_API_KEY=
OPENAI_SUMMARY_MODEL=gpt-4o-mini
OPENAI_EMBEDDING_MODEL=text-embedding-3-small

⚙️ PM2 — padrão de todos os workers

Config central em ecosystem.config.cjs na raiz. Regras:

  • autorestart: false — jobs one-shot, não reiniciam sozinhos ao sair
  • cron_restart — disparo agendado pelo PM2
  • interpreter_args: '--env-file=.env' — carrega o .env relativo ao cwd
  • Logs em .pm2-logs/worker-[nome]-{out,error}.log

🔄 Recriar do zero

  1. Clonar repo e rodar pnpm install --frozen-lockfile
  2. Criar apps/worker/.env a partir do .env.example
  3. pnpm --filter worker build
  4. pm2 start ecosystem.config.cjs
  5. pm2 save (persiste entre reboots)
  6. Opcional: pm2 startup para inicializar no boot da VPS

🧪 Testar um job manualmente

# dry-run (não grava nada)
pnpm --filter worker import:google-business-photos -- --dry-run

# rodar de verdade
pnpm --filter worker import:google-business-photos

# forçar via PM2 agora
pm2 restart worker-google-photos --update-env

🌐 Expor city-agent na web (Nginx)

O city-agent é um daemon HTTP permanente na porta 8787. Para expô-lo no subdomínio agent.luizalmeida.dev, use proxy reverso no Nginx.

Exemplo de configuração:

server {
    listen 80;
    server_name agent.luizalmeida.dev;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 30s;
        proxy_send_timeout 30s;
        proxy_read_timeout 60s;
    }
}

Passos no servidor:

  1. Copiar o exemplo para /etc/nginx/sites-available/agent.luizalmeida.dev
  2. Criar symlink: sudo ln -s /etc/nginx/sites-available/agent.luizalmeida.dev /etc/nginx/sites-enabled/
  3. Testar: sudo nginx -t e sudo systemctl reload nginx
  4. SSL: sudo certbot --nginx -d agent.luizalmeida.dev

Arquivo de exemplo versionado em scripts/nginx/city-agent.conf.
