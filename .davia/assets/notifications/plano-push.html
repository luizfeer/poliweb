🗄️ Modelagem Supabase

Uma tabela única cobre web e nativo. RLS sempre por profile_id e city_id.

create table push_subscriptions (
  id uuid default gen_random_uuid() primary key,
  profile_id uuid references profiles(id) on delete cascade,
  city_id uuid references cities(id),
  platform text check (platform in ('web','android','ios')) not null,
  endpoint text, p256dh text, auth text,
  fcm_token text,
  user_agent text,
  last_seen_at timestamptz default now(),
  created_at timestamptz default now(),
  unique (profile_id, platform, coalesce(endpoint, fcm_token))
);

create table notification_preferences (
  profile_id uuid, city_id uuid, module text,
  channel text check (channel in ('push','email')),
  enabled boolean default true,
  primary key (profile_id, city_id, module, channel)
);

📱 RN shell (Sprint C)

Repo novo apps/mobile/ usando Expo bare + dev client pra builds via EAS sem dor de Xcode.

  • react-native-webview carregando o site Next.
  • @react-native-firebase/messaging pra token FCM.
  • @notifee/react-native pra exibir notificação em foreground.
  • expo-linking pra deep links carmolocal://turismo/....
  • Bridge: WebView onMessage recebe token do JS no site → fetch autenticado pra Server Action registerDevice.
App Review da Apple rejeita "site embrulhado". Push + splash + deep link já cobrem o mínimo, mas vale ter 1-2 telas nativas (login ou perfil) como seguro.

📤 Envio unificado

Edge Function send-push recebe { audience, title, body, url, module } e:

  1. Resolve audiência (ex: cidadãos de Carmo inscritos em events).
  2. Filtra por notification_preferences.
  3. Particiona por plataforma: web-push com VAPID, FCM Admin SDK pra mobile.
  4. Loga em push_deliveries.
  5. Remove subscriptions com 410 Gone (web) ou UNREGISTERED (FCM).
